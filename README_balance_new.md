# 双轮平衡固件 `_new`：接线、烧录与首次调试

更新于 2026-11-24。

## 交付范围

本版使用 ESP32 Dev Module、两块 SimpleFOC Mini、两台 2804、两只 MT6701、一个 MPU6050。四个 STS3215 **先固定姿态**，本程序不发送舵机命令。腿部必须已通过机械固定或独立的舵机控制保持姿态；本程序不会自动让舵机上力，也不会从趴地状态自行起立。

目标是**扶到直立附近后，用两轮维持前后平衡**。代码编译通过不等于实车稳定性已验证；车重、轮径、重心、轴向、绕组参数和输出能力尚未测定，首次必须验证方向、再调参。没有承诺一次烧录就自动站稳。

- 平衡控制参考了 **M创动工坊**的 `Code/BLE-ESP32-BalanceCar/src/main.cpp`，采用 MPU6050 姿态反馈与双电机 FOC 架构。[上游参考提交](https://github.com/macolin007/mcdgf/tree/fce0cbe12ae6b3b5d47ac5b12c97d7ae58bf952d)
- 在本仓库根目录选择 `balance_car_new` 编译及烧录。直接运行 `pio run` 会选择早期传感器测试环境。

核心文件：

| 文件 | 用途 |
|---|---|
| `V1_06_TwoWheel_Balance_Car_new/V1_06_TwoWheel_Balance_Car_new.ino` | Arduino IDE 入口，文件夹内全部文件需一起保留 |
| 同文件夹的 `BalanceController_new.h` | 接线、方向、控制参数、传感器读取与状态控制 |
| 同文件夹的 `BalanceMath_new.h` | 姿态融合、平衡 PID、可选速度环 |
| 硬件 `Wire` / `Wire1` | 左 MT6701 与 MPU6050 共用 Wire，右 MT6701 使用 Wire1 |
| `src/balance_car_new.cpp` | PlatformIO 入口 |

## 1. 接线与安装

| 设备/信号 | 第一路（左轮） | 第二路（右轮） |
|---|---|---|
| SimpleFOC Mini IN1 / IN2 / IN3 | GPIO32 / GPIO33 / GPIO25 | GPIO14 / GPIO27 / GPIO26 |
| SimpleFOC Mini EN | GPIO12 | GPIO13 |
| MT6701 SDA / SCL | GPIO21 / GPIO22 | GPIO17 / GPIO16 |
| MPU6050 SDA / SCL | GPIO21 / GPIO22，与左编码器共用 | — |

- 两只 MT6701 默认地址均为 `0x06`，分别接到 `Wire`（21/22）和 `Wire1`（17/16）。MPU6050 与左侧共用 `Wire`，地址为 `0x68`，AD0 接地；若 AD0 接 3.3 V，则将 `MPU6050_ADDRESS` 改为 `0x69`。
- 接线和上拉见 [WIRING_I2C_new.md](WIRING_I2C_new.md)。程序检查编码器角度读数的通信，但不检查 MT6701 磁场状态；须手动确认磁铁位置和角度反馈可靠。
- 信号线必须上拉到 **3.3 V**，所有设备共地。
- 按随模块提供的兼容说明，`WHO_AM_I` 非 `0x68` 时会打印实际值及兼容警告，再尝试初始化；`0x00`、`0xFF`、I²C 读取失败、配置失败或初始数据异常仍会停机。非标准 ID 的芯片实际兼容性尚须通过静止姿态、手动倾斜及陀螺仪数据检查；不要直接启动平衡。
- MPU6050 的初始化和六轴数据读取参考 Arduino `MPU6050` / `I2Cdev` 实现，寄存器地址写入和读取之间使用 STOP，并检查通信错误与短读。姿态环目标频率为 200 Hz，互补滤波的重力修正时间常数为 1.75 s。
- ESP32、两块驱动、两个编码器、MPU6050、电机电源负极共地。两块驱动用电机电源，舵机由匹配其规格的独立供电供电，不从 ESP32 的 3.3 V 引脚取舵机功率。
- 第一组相线顺序沿用作业的 `32/33/25`，不是上游的 `25/32/33`。每次复位均重新执行 FOC 对齐。
- `POLE_PAIRS=7`、`SUPPLY_VOLTAGE=12`、10 kHz PWM 和 3 V q 轴限幅来自旧作业配置，仍需与两台实际电机、电源核对。2804 尺寸名称本身不能证明极对数和相电阻。
- 没有电流传感器，也未假设相电阻。**3 V 限幅不是 3 A 电流限制**，受阻、持续饱和时应停机检查温升和供电。
- GPIO12 是旧作业沿用的启动配置脚，驱动 EN 不应在 ESP32 复位时将它拉高；若出现启动失败，先检查该电平。
- MPU6050 固定在刚性车架上。当前侧装方式对应传感器 **Z 轴平行车轮轴**，默认用 `gz` 测俯仰角速度，用 X/Y 加速度平面估计俯仰角。安装方式变更时，可在 `BalanceController_new.h` 将 `IMU_PITCH_AXIS` 设为与轮轴平行的 `X`、`Y` 或 `Z`。

实际编译使用 SimpleFOC 2.3.3 的 ESP32 MCPWM 驱动：两路分别使用 MCPWM0 的 A/B 输出，PWM 计时基准共享，因此两路均设置为同一 10 kHz。

## 2. 编译与烧录

已固定 PlatformIO `espressif32@7.1.3`、`esp32dev`、SimpleFOC `2.3.3`；本机编译使用 Arduino-ESP32 2.0.17。MPU6050 直接读寄存器，不另装 MPU6050 库。

在 VS Code / PlatformIO 打开本仓库根目录，然后选择 Project Tasks → `balance_car_new` → Build / Upload。也可在仓库根目录运行以下命令。烧录前接好 USB，支撑车身并架空两轮。

```powershell
pio run -e balance_car_new
pio run -e balance_car_new -t upload
pio device monitor -e balance_car_new -b 115200
```

若接了多个串口设备，Upload 时显式指定实际端口 `--upload-port COMx`，Monitor 时使用 `--port COMx`。打开 Viewer 前先关闭串口监视器。

Arduino IDE：打开上述 `.ino`，选择 ESP32 Dev Module，安装 Espressif ESP32 core 2.0.17 和 SimpleFOC 2.3.3，并保留旁边的 `BalanceController_new.h` 和 `BalanceMath_new.h`。

## 3. 第一次启动必须按顺序完成

1. **支撑车身并架空车轮**，确保四个关节不会塌下。上电后左右轮依次 FOC 对齐，会先转动；这一阶段尚不处理串口 `X`，需要停机时断驱动电源。不能把“默认未使能平衡”理解为初始化阶段轮子绝不转动。
   左轮普通对齐失败后仍会自动尝试右轮对齐，编码器通信故障则跳过后续对齐；任一轮失败都会锁定停机，不能启动平衡。串口会显示左右结果和 SimpleFOC 的对齐细节；打印的供电电压是软件配置值，不是实测值。对齐前后角度只是两个端点，不代表对齐过程中的最大转动量。
2. 对齐结束出现 `CALIBRATE` 时，将车身扶到实际直立姿态并保持静止约 2 秒。固件在此时标定陀螺零偏并把当前俯仰角定为 0°。校准成功后，GUI 显示 `pitch` 与 `set` 均从 0° 开始。校准失败时电机保持未使能，可发送 `C` 重新校准。
   校准可用手扶持。加速度计配置为 ±4 g，静止校准时三轴加速度合量需在 0.70～1.40 g。所选轴陀螺仪平均值绝对值不超过 10 °/s，倾角跨度不超过 30°。陀螺仪标准差超过 1.5 °/s 且不超过 5.0 °/s 时仅打印警告。校准失败时电机保持关闭，可发送 `C` 重试。
3. **检查 MPU6050 方向**。停机时轻轻向前倾，`pitch-set` 应增大，前倾运动中的 `rate` 应为正，停住后 `rate` 回到接近 0。向后倾相反。若前后倾时响应很小，用 `sensor_viewer` 找出变化最大的陀螺仪轴并更新 `IMU_PITCH_AXIS`。若角度和角速度均反向，翻转 `IMU_PITCH_SIGN` 并重新烧录。
4. 扶正、停住轮子，分别发 `L`、`R`。每条命令只驱动对应轮 **0.5 V、200 ms**，随后自动关闭；每次等待完全停下再测试。观察轮胎最上缘是否朝车头运动，即落地后会推车向前。哪侧相反，就只改那侧 `LEFT_MOTOR_SIGN` 或 `RIGHT_MOTOR_SIGN` 并重烧。未转动时不能判定方向，应先检查相线/磁铁/负载；不要通过跳过方向检查来试平衡。
5. 方向都正确后再进行扶持下的地面测试。保持机身距校准平衡角不超过 8°、轮子静止，发送 `A`。前倾应向前追、后倾应向后追；若相反或剧烈振荡，立即 `X`。初次不要完全放手。
6. 初始姿态设得不准确时，先 `X`，扶到新的预期直立姿态后用 `C` 重新静态校准。小幅偏差用 `+/-`，每次 0.1°，相对校准姿态最多调整 ±5°。这是人工确定参考角，并非算法自动识别重心位置。

电源复位、串口监视器触发板子复位时，都可能重新执行第 1 步的轮子对齐。

## 4. 串口命令与调参

波特率 115200。PlatformIO 本环境移除了 `send_on_enter`，单字符按键即可发送；Arduino IDE 串口监视器需点击发送。所有增益/角度调整仅在停机后生效，运行中只处理 `X`。一次发送一条命令。

| 命令 | 动作 |
|---|---|
| `A` | 启动平衡；要求最新有效 IMU、接近直立且轮子静止 |
| `X` | 关闭两路 EN 和输出 |
| `L` / `R` | 限时单轮正向测试，只在架空车轮时使用 |
| `C` | 静止重校准陀螺零偏，将当前姿态重新设为 0° |
| `+` / `-` | 平衡参考角增加/减少 0.1° |
| `1` / `0` | 倾角 Kp 增加/减少 0.5 |
| `5` / `4` | 倾角 Ki 增加/减少 0.1，初值为 0 |
| `3` / `2` | 角速度 Kd 增加/减少 0.02 |
| `V` | 切换慢速轮速 PI 外环，默认开启 |
| `?` | 查看当前 Kp、Ki、Kd、参考角、方向和速度环状态 |

姿态环初值为 Kp=56.0 V/rad、Ki=0 V/(rad·s)、Kd=1.90 V/(rad/s)。驱动使用 12 V 母线，平衡控制的 q 轴电压指令限幅 ±3 V。该组参数基于固定腿姿态、假设车身质量与惯量的模型复算，适用于扶持试调。计算与仿真见 [默认参数计算说明](analysis/revised_motor_pid/balance_defaults.md)，实时曲线与详细操作见 [BALANCE_VIEWER_TUNING.md](BALANCE_VIEWER_TUNING.md)。

确认纠偏方向后，先用默认双环做扶持下约 1° 的小扰动试验。来回明显振荡时先停机，检查方向、延迟和结构松动，再考虑降低 Kp 或调整 Kd。输出持续达到 ±3 V 时，检查供电、负载和可用转矩。

默认慢速轮速外环以零速度为目标，Kp=0.31 deg/(rad/s)、Ki=0.20 deg/rad，倾角参考修正最大 ±1°。该环负责减小前后速度，位置会随纠偏移动。仅在扶持下做单环诊断时，可在 `X` 停机后用 `V` 切换，再通过 `?` 核对状态。

串口调参保存在 RAM，复位会恢复初值。验证成功后，将值写入 `BalanceController_new.h` 的 `INITIAL_ANGLE_KP`、`INITIAL_ANGLE_KI`、`INITIAL_ANGLE_KD` 等配置再编译；方向必须在源文件中修改。

输出例（仅字段说明，不是实测数据）：

```text
pitch=... set=... rate=... wl=... wr=... u=... lean=... A=0 T=0 F=0 imu_us=... foc_us=...
```

`pitch/set/lean` 单位度，`rate` 度/秒，`wl/wr` 按配置方向换算为轮子 rad/s，`u` 是共同 q 轴电压命令。`A` 为平衡使能，`T=1/2` 为左右单轮测试，`F=1` 为故障锁定。

`imu_us` 是最近一次 MPU6050 硬件 I²C 读取耗时，单位微秒；`foc_us` 是自上次成功发送遥测以来、两轮控制使能期间主 FOC 循环的最大间隔，单位微秒。同步读取会占用主循环，须在实车检查时序。

## 5. 停机与验证边界

- 超过校准直立角 ±35°会停机，需扶正、轮子停下后重新发 `A`。架空调试时可用 `STOP X` 结束测试，轮速超过原 30 rad/s 门槛时继续运行。
- 编码器 I²C 错误或短读、MPU6050 读取异常或控制间隔超 30 ms 会锁定故障。平衡环使能后，若俯仰平面加速度分量过低，姿态估计可从上一帧有效加速度起最多 30 ms 仅用陀螺仪更新。分量持续过低会停机。再次发送 `A` 会重报锁定原因，修复后须复位。平衡固件两侧总线均用 100 kHz 排查编码器通信故障，两侧超时均为 3 ms。
- 待机时加速度计或陀螺仪饱和会进入 `IMU WAIT`。保持车身直立静止，读数恢复且距最近一次饱和至少 100 ms 后显示 `IMU RECOVERED`，此时可重新发送 `A` 或 `L/R`。驱动期间的饱和会停机并锁定故障。
- EN 在进入库停机方法之前先拉低，只有已初始化并链接成功的驱动才调用库停机函数。
- 遥测最多约 20 Hz，串口发送空间不足时丢弃该帧。主循环反复执行 FOC，姿态环目标频率 200 Hz；同步 I²C 读取期间不会执行 FOC 更新，实际间隔需结合 `imu_us/foc_us` 和实车测量评估。
- 超时检查在主循环恢复执行时触发，不是独立硬件急停/看门狗；完全死机、掉电、机械倒塌不能靠这些软件检查补救。

主机测试覆盖共享总线读数、初始化失败、过期 IMU 拒绝使能、`X` 停机、单轮测试、传感器失联、无效轮速、过倾、控制超时及控制数学。

**实车待验证**。烧录当前版本后，按启动流程核对安装方向和轮子转向，再验证控制周期、负载下的转矩、温升和动态平衡。

主机回归测试（需要 g++，本机已具备）：在工程根目录执行 `.\tests\balance_car_new\run_new.ps1`。测试使用模拟接口，不会连接或驱动电机。
